用于指导 AI 完成本次代码提交。执行过程中必须保持渐进式确认：只有在暂存区和工作区同时存在内容时，才需要询问用户是否同意将工作区内容加入暂存区；其他场景按流程直接执行。

## 执行流程

### 1. 检查暂存区与工作区状态

先分别检查暂存区和工作区是否存在变更。

- **暂存区和工作区都没有内容**：退出流程，并明确说明当前没有可提交内容。
- **暂存区和工作区都有内容**：询问用户是否同意将工作区内容添加到暂存区。
  - 用户同意后，执行添加操作，再继续后续流程。
  - 用户不同意时，仅基于当前暂存区内容继续提交。
- **只有工作区有内容**：直接将工作区内容添加到暂存区。
- **只有暂存区有内容**：直接进入后续流程。

### 2. 获取本次变更文件名列表

获取暂存区中本次即将提交的文件名列表，用于判断提交范围、生成 scope，并排除不适合完整读取 diff 的大型文件。

### 3. 获取变更详情

一次性获取本次变更文件的 diff 内容，理解代码变更详情。

读取 diff 时必须排除大型或低价值文件，例如：

- `package-lock.json`
- `pnpm-lock.yaml`
- `yarn.lock`
- `bun.lockb`
- 其他明显由工具生成、内容巨大或不适合人工审阅的锁文件/构建产物

如果排除文件本身也发生变化，应在提交信息中概括说明依赖或锁文件发生更新，但不要展开其完整 diff。

### 3.5. 代码评审

在获取 diff 内容后、生成提交信息前，对变更内容进行代码评审。

#### 评审内容

针对 diff 内容进行评审，重点关注：

- 代码逻辑正确性
- 代码规范符合性
- 潜在的安全风险
- 性能影响
- 可维护性
- 与现有代码的一致性

#### 评审标准

发现并列出潜在问题，每个问题需包含：

- **说明**：清晰描述问题现象
- **修改建议**：提供具体的修改方案
- **问题定级**：
  - **严重**：必须修改（如安全漏洞、功能错误、重大性能问题）
  - **一般**：建议修改（如代码规范问题、可维护性问题）
  - **轻微**：可以不改（如格式问题、不影响功能的细节）

#### 评审结果处理

- 若评审后未发现潜在问题，继续执行后续提交流程
- 若评审后发现**严重**或**一般**级别的问题，停止提交代码，向用户展示评审结果
- 用户确认修复所有问题后，重新执行评审流程
- 只有评审通过后，才能继续生成提交信息

### 4. 生成提交信息并直接提交

基于暂存区文件列表和 diff 内容生成提交信息，然后直接执行提交。

提交信息格式必须满足：

- **头部**：`type(scope): message`
  - 总长度不超过 90 个字符。
  - `type` 使用 Conventional Commits 常见类型，例如 `feat`、`fix`、`refactor`、`docs`、`test`、`chore`、`build`、`ci`、`style`、`perf`。
  - `scope` 使用最能概括变更范围的英文短词；范围不明确时可省略 scope，使用 `type: message`。
  - `message` 使用简洁中文描述本次提交的核心目的。
- **Body**：每行一个主要变更项描述。
  - 每行以 `- ` 开头。
  - 每行不超过 90 个字符。
  - 只描述真实发生的主要变更，不编造未确认内容。
  - 每项之间不要留多余空行。
- **Footer**：不需要 footer。

提交完成后，简要告知用户提交成功，并给出本次提交的提交信息摘要。

## 注意事项

- 不要提交未被用户允许加入暂存区的工作区内容。
- 不要为了生成提交信息而修改业务代码。
- 如果提交失败，说明失败原因，并给出下一步建议。
- 如果发现暂存区内容可能包含敏感信息，应暂停提交并提醒用户确认。
- 如果提交钩子修改了文件或导致暂存区状态变化，应重新检查状态并说明情况。

## Git 命令附录

以下命令供执行流程参考，实际使用时应根据仓库状态选择必要命令。

### 检查状态

```bash
git status --short
```

检查暂存区是否存在变更：

```bash
git diff --cached --quiet
```

检查工作区是否存在未暂存变更：

```bash
git diff --quiet
```

检查未跟踪文件：

```bash
git ls-files --others --exclude-standard
```

### 添加工作区内容到暂存区

```bash
git add -A
```

### 获取本次提交文件列表

```bash
git diff --cached --name-only
```

### 获取暂存区 diff

获取全部暂存区 diff：

```bash
git diff --cached -- .
```

排除大型锁文件后获取暂存区 diff：

```bash
git diff --cached -- . ':(exclude)package-lock.json' ':(exclude)pnpm-lock.yaml' ':(exclude)yarn.lock' ':(exclude)bun.lockb'
```

### 提交代码

不要使用多段 `-m` 参数拼接提交信息；这会让 Body 的每一项之间产生多余空行。应先写入提交信息文件，再通过 `git commit -F` 提交：

```bash
cat > .git/COMMIT_MSG <<'EOF'
type(scope): message

- 主要变更项一
- 主要变更项二
EOF
git commit -F .git/COMMIT_MSG
rm .git/COMMIT_MSG
```

提交后查看最近一次提交：

```bash
git log -1 --oneline
```
