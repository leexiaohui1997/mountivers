# 图片质量校验

我发送的这张图片由 AI 按下面的生图提示词生成，请对它做质量校验。

## 生图提示词

> <%- prompt %>

## 校验维度（对照提示词逐项检查）

1. **提示词符合度**：构图、风格、色彩是否符合生图提示词要求；画面主体与场景是否与提示词描述对应。主体与核心元素对得上即可，不要求每个细节逐项复刻。
2. **画面比例**：实际画面比例是否符合生图提示词要求（如 2054x1600 横版、16:9 横版），是否因裁切、拉伸、拼接、上下补白导致比例不符；按画面宽高关系判断即可，不要求精确到像素。
3. **画面文字**：是否有多余文字、乱码；要求出现的画面文字（大字/小字）是否清晰、内容正确、无错别字。
4. **水印与标识**：是否残留水印、二维码、平台标识（注意：经去水印处理的图片仍需复核水印是否清干净）。
5. **风格统一**：是否保持合集统一视觉基调——漫画/绘本/手绘插画质感（非写实摄影）、低饱和暖色调、大面积留白、情绪克制有故事感；封面与合集封面风格是否一致。同一合集方向一致即可，允许轻微色彩、留白差异。
6. **画面质量**：主体是否完整无裁切缺失；有无明显畸变、肢体错误、元素崩坏。不影响主体识别和使用的小瑕疵不算不合格。

## 判定尺度（抓大放小，避免过度质检）

以“是否影响发布使用”为准，不要追求完美：

- **必须判不合格（硬伤）**：画面比例明显不符；主体缺失、跑题或严重变形；要求的画面文字缺失、错字或乱码；残留水印、二维码、平台标识；大面积裁切、明显肢体错误、元素明显崩坏。
- **不要判不合格（可接受的轻微瑕疵）**：轻微色差；细小的纹理、线条、光影不完美；构图与提示词有小的出入；背景里不影响主体的小元素；风格“还可以更好”但不影响阅读。这类不要判不合格，也不要因此触发重新生成；如果确有明确、值得说明的改进点，可以简短写进该检查项 `pass=true` 的 `reason`，没有就留空。
- 判断标准是“发布后读者是否会发现明显问题”，不是“能否做到更完美”。拿不准时按通过处理。

## 输出要求

只依据画面实际内容判断，不臆测。`checks` 必须逐一列出上方 6 个校验维度，一项不落；每项按上面的「判定尺度」校验，只有影响发布使用的实质问题才 `pass: false`，并在 `reason` 中写清具体问题（如"画面文字：小字第三个字为乱码"），不写"效果一般"这类模糊表述，也不要把轻微瑕疵写成不合格。

`pass: false` 时 `reason` 必须写清具体问题；`pass: true` 时通常留空，但对“可以通过、仍有改进空间”的项，可以简短写一条非阻塞建议（仍保持 `pass: true`，不触发重生成），没有就留空。整体 `pass` 为所有检查项全部通过。

`score`：0~100 的整数综合评分，**即使 `pass: true` 也必须给出**。评分只用于失败重试时挑选最佳结果，不改变 `pass` 判定。参考：90~100 无硬伤、可直接发布；75~89 有轻微问题但不影响使用；60~74 有明显问题但勉强可用；0~59 硬伤严重、基本不可用。

若存在不通过项，`suggestion` 必须直接给出**调整后的完整生图提示词**：该字段会被原样用于重新出图，因此必须是可直接生图的最终提示词（完整、单段、保留原有的比例/画幅与画面文字要求，并修复所有不通过项）；不要写“建议”“可以”“调整方向”之类的说明性文字，也不要在前面加“调整后提示词示例：”等标签。轻微瑕疵不要为了“更好”而重生成。整体合格时 `suggestion` 必须留空，即使某些检查项附了非阻塞改进建议（不会重新出图）。

以 json 代码块回复，schema 如下（未列字段一律不写）：

```jsonc
{
  "pass": true, // 整体是否合格：所有检查项全部通过才为 true
  "score": 85, // 0~100 综合评分；即使合格也要给出
  "checks": [
    {
      "name": "提示词符合度", // 校验维度名，与上方 6 个维度一一对应
      "pass": true, // 该检查项是否通过
      "reason": "", // pass=false 写具体问题；pass=true 可写非阻塞改进建议，没有则留空
    },
    // ...其余维度同理，共 6 项
  ],
  "suggestion": "", // 调整后的完整生图提示词，可直接用于重新出图（整体合格则留空）
}
```

只回复一个 JSON 代码块，JSON 之外最多加一句"已生成 check.json"。
